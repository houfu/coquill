CoQuill runs entirely inside Claude. There is no server to spin up, no database to configure, and nothing to host. You install it once with a single command and it is available across every Cowork project on your account.

<Aside type="note">
  Docassemble, the most capable open-source alternative, requires a Linux server running Docker and ongoing maintenance. HotDocs requires an enterprise deployment engagement before the first document can be produced.
</Aside>

## One install, two clients

Both Claude Cowork and Claude Code install CoQuill the same way: by adding the plugin marketplace.

**Claude Cowork** -- open any Cowork project and run:

```
/plugin marketplace add houfu/coquill
/plugin install coquill@coquill
```

**Claude Code** -- run the same commands in your terminal:

```bash
/plugin marketplace add houfu/coquill
/plugin install coquill@coquill
```

That is the entire installation process. CoQuill is now available everywhere -- in any Cowork project, in any Claude Code workspace, on every machine where you sign in.

## Installed once, available everywhere

CoQuill installs at the account level, not per-project. After install, every Cowork project you open already has CoQuill ready to use. No per-folder setup, no copy-pasting skills into each project, no re-installation when you start a new piece of work.

## Dependencies handle themselves

CoQuill relies on a handful of Python packages -- `docxtpl`, `pyyaml`, `jinja2`, and `weasyprint`. You never need to install them manually. When a skill runs, it installs any missing packages automatically. After the initial install, everything is cached locally.

## No separate app

There is no standalone application, no Electron window, no browser tab to keep open. CoQuill lives where Claude already lives. You interact with it through the same conversation interface you use for everything else in Claude Cowork or Claude Code.

That means zero context-switching. Ask Claude to prepare a document with CoQuill, answer a few questions, and the finished file appears in your `output/` folder -- all without leaving the chat.

## Share template stacks with a colleague

Because CoQuill is installed once per account, sharing a stack of templates with a colleague is just sharing the templates. Zip up a `templates/` folder, send it to a teammate who already has CoQuill installed, and they drop it into a Cowork project of their own to start producing the same documents.

No deployment, no shared server, no access management. The whole template stack travels in a zip file. The CoQuill engine is already on their account.

## Your files stay local

Templates are local files, rendering happens on your machine, and output stays on your disk. No cloud uploads, no waiting for a remote server to respond.

CoQuill requires an active Claude session -- but your documents never leave your machine.
